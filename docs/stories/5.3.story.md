# Story 5.3: Intégration des recognizers réels (CTC & LLM)

## Status

Ready for Review

## Story

**As a** ingénieur,
**I want** brancher les modèles Omnilingual réels derrière l'interface existante,
**so that** je les évalue sans modifier l'API ni l'app.

## Acceptance Criteria

1. Les implémentations CTC (`omniASR_CTC_300M_v2`, sans `lang`) et LLM (`omniASR_LLM_300M_v2`, `lang=["dje_Latn"]`) respectent l'interface `SpeechRecognizer`.
2. Le service ASR se déploie/redémarre indépendamment de l'API (image Docker ASR lourde séparée).
3. Le passage de Mock à un modèle réel se fait par configuration, sans changement d'API ni de mobile.
4. Un test de fumée confirme une reconnaissance réelle de bout en bout sur la ressource GPU retenue.

## Dev Notes

### Contexte & objectif

Story du track **ML/Infra ASR** : elle branche les **vrais modèles** Omnilingual (CTC & LLM)
derrière l'abstraction `SpeechRecognizer` livrée en story 2.2 — **sans modifier l'API ni le
mobile**. C'est la concrétisation du principe « moteur vocal remplaçable » : changer de modèle =
changer une **variable d'environnement**. Elle est indépendante des autres stories d'Epic 5
(corpus 5.1, harnais 5.2) : elle ne dépend que de l'interface 2.2. Le harnais (5.2) et la
sélection (5.4) l'utiliseront ensuite pour comparer CTC vs LLM. [Source: architecture.md#High Level Architecture] [Source: docs/prd/requirements.md#FR9]

> **Gate GPU (bloquant Epic 5)** : cette story requiert la **décision de ressource GPU** (cloud
> Modal vs autre) — risque n°1 du projet. Le code (`remote.py`, factory, service `services/asr`)
> peut être **écrit** en amont ; le **test de fumée AC4** nécessite la ressource GPU réelle. Tant
> que le GPU n'est pas décidé/déployé, l'API tourne en `ASR_MODE=mock`. [Source: docs/prd/epic-5 (intro : « gaté par la décision de ressource GPU »)]

### Dépendances (toutes créées)

- **2.2 (Done)** : `SpeechRecognizer` Protocol (`transcribe(AudioInput) -> AsrResult`, `model_version`),
  `AudioInput`, `AsrResult` (text, acoustic_score, candidates, latency_ms, model_version), et
  `factory.get_recognizer(settings)` avec le `TODO Epic 5` prêt à être levé. [Source: services/api/app/asr/base.py] [Source: services/api/app/asr/factory.py]
- **config.py (créé)** : `ASR_MODE = Literal["mock","ctc","llm"]` déjà défini (défaut `mock`). [Source: services/api/app/config.py]

### Contrat externe Modal `/transcribe`

```
POST /transcribe   (endpoint HTTPS Modal, token secret via .env)
Body: audio (WAV PCM16 mono 16kHz)
200:  { text, acoustic_score, candidates[], latency_ms, model_version }
```

Encapsulé par `RemoteCtcRecognizer` / `RemoteLlmRecognizer` ; en cas d'échec/cold start →
timeout + repli `decision=repeat` (aucun nombre inventé). Alternatives interchangeables
(Replicate, HF Inference Endpoints, VM GPU) sans changer API ni mobile. [Source: architecture.md#External APIs — Modal] [Source: architecture.md#Performance Optimization — Backend]

### Contraintes techniques clés

- **ASR via l'interface uniquement (NFR9)** : l'API n'appelle jamais un modèle directement —
  toujours via `SpeechRecognizer`. Changer de modèle = config, pas de code applicatif. [Source: architecture.md#Coding Standards — « ASR via l'interface uniquement »]
- **Déploiement indépendant (AC2)** : image ASR lourde séparée, `modal deploy services/asr/app`,
  redémarrable sans toucher l'API. [Source: architecture.md#Deployment Architecture — ASR Deployment]
- **Secrets hors Git (NFR3)** : token Modal + `ASR_ENDPOINT_URL` via `.env`/secrets, jamais côté
  mobile ni en dur. [Source: architecture.md#Security Requirements — Authentication Security] [Source: architecture.md#External APIs — Modal (Authentication)]
- **CI sans GPU** : Mock en CI ; smoke réel hors pipeline standard. [Source: architecture.md#CI/CD Pipeline]
- **Jamais de nombre inventé** : sur échec ASR, repli `repeat` — la politique (2.5) et le moteur
  (Epic 1) restent la source de vérité. [Source: architecture.md#Coding Standards — « Jamais de nombre inventé »]
- **Hors périmètre 5.3** : mesure Exact Number Accuracy & matrice de confusions (5.2), **choix**
  CTC vs LLM (5.4), calibration confiance (5.5). [Source: docs/prd/epic-5]
