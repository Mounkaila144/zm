# Story 2.7: Rate limiting et durcissement de l'API

## Status

Done

## Story

**As a** responsable sécurité,
**I want** limiter et sécuriser l'accès à l'API,
**so that** je protège le service contre les abus et les fuites.

## Acceptance Criteria

1. Un rate limiting est appliqué sur les endpoints sensibles (notamment `/recognize`).
2. Les erreurs sont normalisées et n'exposent ni stack trace ni donnée interne.
3. Les identifiants clients sont anonymes.
4. Des tests vérifient le déclenchement du rate limiting et le format des erreurs.

### Rate limiting — slowapi

```python
# services/api/app/core/rate_limit.py (structure)
from slowapi import Limiter
from slowapi.util import get_remote_address
from starlette.requests import Request

def anonymous_key(request: Request) -> str:
    # Clé anonyme : anon_id si fourni, sinon IP (non persistée comme PII)
    anon = request.query_params.get("anon_id")  # + form si multipart
    return anon or get_remote_address(request)

limiter = Limiter(key_func=anonymous_key)
```

```python
# app/main.py (extraits)
from slowapi.errors import RateLimitExceeded
from slowapi.middleware import SlowAPIMiddleware
app.state.limiter = limiter
app.add_middleware(SlowAPIMiddleware)
app.add_exception_handler(RateLimitExceeded, rate_limit_handler)  # -> ApiError code=RATE_LIMITED, 429
```

```python
# app/api/v1/recognize.py
@router.post("/recognize", ...)
@limiter.limit(get_settings().RATE_LIMIT_RECOGNIZE)
async def recognize(request: Request, audio: UploadFile = File(...), anon_id: ... , ...):
    ...
```

### Enveloppe d'erreur normalisée (invariant transverse)

```python
# Toute erreur -> même forme (déjà définie dans errors.py)
{
  "error": {
    "code": "RATE_LIMITED" | "VALIDATION_ERROR" | "AUDIO_INVALID" | "INTERNAL" | ...,
    "message": "<message sûr, sans détail interne>",
    "request_id": "<uuid>",
    "timestamp": "<ISO 8601 UTC, suffixe Z>"
  }
}
```

Handlers à enregistrer dans `create_app()` : `RateLimitExceeded` (429), `RequestValidationError`
(422), `HTTPException` (status conservé), `Exception` (500). Aucun ne renvoie de stack trace,
chemin, SQL, audio ou secret. [Source: architecture.md#Error Handling Strategy — Error Response Format] [Source: architecture.md#Coding Standards — « Erreurs sans fuite »]

### Contraintes techniques clés

- **Anonymat (NFR7)** : identité = `anon_id` (UUID device), pas d'auth utilisateur MVP. L'IP
  ne sert que de clé de rate limit volatile, jamais persistée/loggée comme PII. [Source: architecture.md#Authentication and Authorization] [Source: architecture.md#Tech Stack — Authentication]
- **Logs sans PII (NFR6)** : structlog JSON, `request_id` uniquement ; jamais d'audio, de texte
  brut sensible, de secret. [Source: architecture.md#Monitoring — Logs sans PII] [Source: architecture.md#Error Handling Strategy]
- **Config via settings** : limites et niveau de log lus via `Settings` (`RATE_LIMIT_RECOGNIZE`,
  `LOG_LEVEL`), aucun secret en dur. [Source: architecture.md#Coding Standards — « Config via objet settings »]
- **Erreurs sans fuite** : toutes les routes passent par le handler normalisé — invariant
  explicitement rattaché à cette story. [Source: architecture.md#Coding Standards — « Erreurs sans fuite » (story 2.7)]
- **Hors périmètre 2.7** : CORS/TLS gérés au niveau nginx/déploiement (hors code applicatif) ;
  protection `/recordings` et audio consenti en Epic 4 ; calibration en Epic 5. [Source: architecture.md#Security Requirements] [Source: docs/prd/epic-2]
