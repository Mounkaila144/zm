# Story 4.1: Consentement explicite versionné

## Status

Done

## Story

**As a** contributeur,
**I want** comprendre et accepter clairement comment ma voix sera utilisée,
**so that** je contribue en confiance et je peux me rétracter.

## Acceptance Criteria

1. Un écran de consentement présente un texte versionné (usage, anonymat, conservation, retrait) avant toute contribution.
2. Le consentement (version acceptée, horodatage, identifiant anonyme) est enregistré.
3. Aucune collecte conservée n'a lieu sans consentement explicite ; l'audio ordinaire reste supprimé par défaut.
4. Le texte et la version du consentement sont traçables côté serveur.

## Dev Notes

### Contexte & objectif

Première story du track **Collecte consentie** (Epic 4). Elle établit le **socle éthique** : un
consentement explicite, versionné et traçable, **prérequis obligatoire** à toute conservation de
voix. Elle est indépendante car elle ne réutilise que des briques déjà créées : la fondation
mobile 3.1 (écran + garde) et la couche DB de la story 2.6 (session, Base, Alembic, Repository
Pattern). Les stories suivantes de l'Epic 4 (4.2 prompts/enregistrement consenti, 4.3 upload
`/recordings`) s'appuient dessus. [Source: architecture.md#High Level Architecture] [Source: docs/prd/epic-4]

### Dépendances (toutes créées)

- **3.1 (Approved)** : navigation `/contribute`, garde fonctionnelle (`contributionGuard`,
  `consentStatusProvider`), `ApiClient`, `anonIdProvider`, arborescence `features/contribution/`. [Source: docs/stories/3.1.story.md] [Source: architecture.md#Frontend Architecture — Protected Route Pattern]
- **2.6 (créée)** : `db/session.py`, `db/models.py` (Base + Alembic), Repository Pattern → réutilisés
  pour `consents` + `ConsentRepo`. [Source: docs/stories/2.6.story.md] [Source: architecture.md#Backend Architecture — Data Access Layer]

### Modèle de données `Consent`

```sql
CREATE TABLE consents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    anon_id         TEXT NOT NULL,
    consent_version TEXT NOT NULL,
    accepted_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    withdrawn       BOOLEAN NOT NULL DEFAULT false,
    withdrawn_at    TIMESTAMPTZ
);
CREATE INDEX idx_consents_anon ON consents(anon_id);
```

Types **portables** SQLAlchemy 2.0 (comme 2.6) pour SQLite↔PostgreSQL. Le champ `withdrawn`
prépare le retrait (story 4.4). [Source: architecture.md#Database Schema — consents] [Source: docs/stories/2.6.story.md]

### Contrats API `/consent`

```
GET /api/v1/consent
200: { "consent_version": "<str>", "text": "<str>" }   # texte + version courants

POST /api/v1/consent
Body: { anon_id, consent_version }   (+ acceptation)
201: consentement enregistré
```

[Source: architecture.md#API Specification — /consent]

### Contraintes techniques clés

- **Pas de collecte sans consentement (FR19/FR20)** : le consentement est le **guard** de toute
  conservation ; l'audio ordinaire de `/recognize` reste supprimé par défaut. L'upload consenti
  (4.3) exigera `require_valid_consent`. [Source: architecture.md#Backend Architecture — Authentication (`require_valid_consent`)] [Source: docs/prd/requirements.md#FR19]
- **Traçabilité versionnée (FR19)** : la version acceptée est persistée ; le texte est une
  ressource versionnée serveur. [Source: docs/prd/requirements.md#FR19]
- **Anonymat (NFR7)** : identité = `anon_id` ; aucune donnée personnelle. [Source: architecture.md#Authentication and Authorization]
- **Config via settings / logs sans PII** : cohérent avec les standards backend. [Source: architecture.md#Coding Standards] [Source: architecture.md#Monitoring — Logs sans PII]
- **Hors périmètre 4.1** : génération de prompts + enregistrement consenti (4.2), endpoint
  `/recordings` + stockage sécurisé (4.3), retrait effectif de l'audio (4.4), validation dataset
  (4.5). [Source: docs/prd/epic-4]
