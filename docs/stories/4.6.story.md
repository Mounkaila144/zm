## Dev Notes

### Contexte & objectif

Story **backend indépendante** : elle transforme les données déjà persistées (reconnaissances +
feedbacks, story 2.6) et le lexique versionné (Epic 1) en **métriques de pilotage qualité**,
exposées via un endpoint interne `/metrics`. Elle ne dépend d'aucune story non créée — c'est un
consommateur en lecture des tables `recognitions`/`feedbacks` et du statut lexical. Idéale pour
le track backend/données en parallèle du mobile. [Source: architecture.md#Monitoring and Observability] [Source: docs/prd/epic-4]

### Dépendances (toutes créées)

- **2.6 (créée)** : tables `recognitions` (latences, decision, versions) et `feedbacks`
  (`feedback_type`, versions) + couche DB async / repositories. [Source: docs/stories/2.6.story.md] [Source: architecture.md#Database Schema]
- **Epic 1 (Done)** : `zarma_numbers` expose le lexique versionné avec statuts `validé`/`unresolved`
  et `grammar_version`. [Source: docs/prd/requirements.md#FR7] [Source: packages/zarma_numbers — Lexicon]

### Métriques attendues (source : Monitoring)

- **Taux confirmation / correction / rejet** ← `feedbacks.feedback_type`. [Source: architecture.md#Monitoring — Key Metrics]
- **Latence totale / ASR** ← `recognitions.latency_total_ms` / `latency_asr_ms` (NFR1). [Source: architecture.md#Monitoring — Key Metrics]
- **Couverture linguistique** : `validé` vs `unresolved` (lexique). [Source: architecture.md#Monitoring — Key Metrics]
- (Exact Number Accuracy + matrice de confusions relèvent du **benchmark Epic 5**, pas de 4.6.) [Source: architecture.md#Monitoring — Key Metrics (Epic 4/5)]

### Contraintes techniques clés

- **Lecture seule / agrégats** : `/metrics` ne modifie rien ; il agrège. Aucune PII, aucun
  `anon_id` individuel exposé. [Source: architecture.md#Monitoring — Logs sans PII] [Source: architecture.md#Authentication and Authorization]
- **Source unique lexique** : la couverture linguistique vient de `zarma_numbers`, jamais
  recalculée à la main. [Source: architecture.md#Coding Standards — « Isolation du moteur linguistique »]
- **Versions systématiques** : `grammar_version` (et éventuellement `model_version` observés)
  accompagnent les agrégats. [Source: architecture.md#Coding Standards — « Versions systématiques »]
- **Endpoint interne** : observabilité/pilotage, cohérent avec structlog + `/health` + Uptime Kuma. [Source: architecture.md#Monitoring — Monitoring Stack]
- **Hors périmètre 4.6** : métriques de benchmark ASR (Exact Number Accuracy, matrice de
  confusions) = Epic 5 ; tableau de bord riche post-MVP. [Source: architecture.md#Monitoring — Key Metrics]
