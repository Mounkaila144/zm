# Story 5.1: Corpus de benchmark avec split par locuteur

## Status

Done

## Story

**As a** responsable données,
**I want** un corpus d'évaluation propre et représentatif,
**so that** je mesure la qualité sans fuite de données.

## Acceptance Criteria

1. Le corpus contient ≥ 100 audios, plusieurs locuteurs, nombres courts/longs et paires de confusion.
2. Le jeu de test est séparé **par locuteur** : aucune voix de test n'apparaît ailleurs.
3. Chaque audio est étiqueté avec le nombre attendu (vérité terrain) et des métadonnées (locuteur anonyme, région si connue, condition calme/bruit).
4. Le corpus est reproductible (script de constitution + manifest versionné).

## Dev Notes

### Contexte & objectif

Première story du track **Benchmark/ML** (Epic 5), **indépendante** et **sans GPU** : elle
constitue un corpus d'évaluation reproductible avec **split strict par locuteur** (anti-fuite),
étiqueté en vérité terrain. Ce corpus est le socle sur lequel le harnais d'évaluation (5.2)
mesurera l'Exact Number Accuracy et comparera CTC vs LLM (5.4). Elle ne dépend que du moteur
déterministe `zarma_numbers` (Epic 1) pour les cibles/formes et les paires de confusion. [Source: architecture.md#High Level Architecture] [Source: docs/prd/epic-5]

> **Note de gating (Epic 5)** : l'Epic 5 est globalement gaté par la **décision de ressource GPU**
> (risque n°1). **La story 5.1 n'est PAS gatée** : constitution de corpus + manifest, aucune
> inférence ni GPU requis — elle peut démarrer immédiatement. [Source: docs/prd/epic-5 (intro + « tout ce qui précède peut être livré via MockRecognizer »)]

### Dépendances (toutes créées)

- **Epic 1 (Done)** : `zarma_numbers.generate(n)` (formes canoniques cibles), lexique versionné
  et `asr_confusions` (paires de confusion). [Source: packages/zarma_numbers]
- Aucune dépendance à une story non créée. (5.2 dépendra de **ce** corpus.) [Source: docs/prd/epic-5]

### Structure & manifest cibles

```text
dataset/
├── raw/            # (git-ignored) audio consenti / brut
├── benchmark/      # audios d'évaluation
└── manifests/      # manifest versionné, split par locuteur
scripts/bench/      # script de constitution + validation
```

Manifest (une entrée par audio) — champs minimaux :
`audio_path, expected_number, speaker_key, region?, condition(calme|bruit), split(test|dev)`.
[Source: architecture.md#Unified Project Structure] [Source: docs/prd/epic-5 AC3]

### Contraintes techniques clés

- **Split par locuteur strict (NFR10)** : aucune voix de test ailleurs — invariant vérifié par
  le script et testé. [Source: architecture.md#Data Models — Contribution] [Source: docs/prd/epic-5 AC2]
- **Reproductibilité (AC4)** : script + manifest versionnés ; audio brut git-ignored. [Source: architecture.md#Unified Project Structure]
- **Métrique de décision = Exact Number Accuracy** (pas le WER) — le corpus est conçu pour la
  mesurer (calme/bruit, courts/longs, confusions). La mesure elle-même est en 5.2. [Source: docs/prd/epic-5 — story 5.2 AC1]
- **Source unique moteur** : cibles et confusions viennent de `zarma_numbers`, jamais dupliquées. [Source: architecture.md#Coding Standards — « Isolation du moteur linguistique »]
- **Consentement / éthique** : uniquement de l'audio consenti dans le benchmark. [Source: docs/prd/epic-4] [Source: docs/prd/requirements.md#FR19]
- **Hors périmètre 5.1** : harnais d'évaluation & matrice de confusions (5.2), recognizers réels
  (5.3), sélection modèle (5.4), calibration (5.5). [Source: docs/prd/epic-5]

### Testing

**Emplacement** : tests du script sous `services/asr/tests/` ou `scripts/bench/`. [Source: architecture.md#Testing Strategy — E2E/Benchmark]

**Standards de test :** intégrité manifest, non-fuite de locuteur, couverture (courts/longs/confusion),
reproductibilité (deux runs identiques). **Sans GPU**. [Source: architecture.md#Testing Strategy — Testing Pyramid]

**Exécution** : script de constitution + `uv run pytest` sur les tests du corpus. [Source: architecture.md#Development Commands]
