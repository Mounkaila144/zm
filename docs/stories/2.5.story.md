# Story 2.5: Confiance composite et politique d'ambiguïté

## Status

Done

## Story

**As a** utilisateur,
**I want** que le système hésite plutôt que de se tromper,
**so that** je garde le contrôle et j'évite les erreurs numériques silencieuses.

## Acceptance Criteria

1. Un score de confiance composite combine signaux acoustique, grammatical, variante connue, marge entre candidats et historique de confusions.
2. La politique produit une décision explicite : accepter / demander confirmation / demander répétition.
3. En cas d'ambiguïté, la réponse inclut les alternatives candidates ordonnées.
4. Le système ne retourne jamais un nombre pour une phrase non numérique (rejet ou répétition).
5. Les poids/seuils sont configurables (valeurs par défaut documentées ; calibration réelle en Epic 5).
6. Des tests couvrent haute confiance, ambiguïté (deux candidats proches) et rejet.

## Dev Notes

### Contexte & objectif

Les stories 2.3 (pipeline) et 2.4 (audio sécurisé) ont livré un `/recognize` fonctionnel
mais avec une décision **binaire provisoire** : `accept` si le parsing réussit, `repeat`
sinon, `confidence` figée à `1.0`/`0.0`. La story 2.5 remplace cette logique par le vrai
cœur « prudent » du produit : un **score composite** (5 signaux) et une **politique
explicite** accept/confirm/repeat, avec **alternatives ordonnées** en cas d'ambiguïté.
C'est ce qui matérialise le principe directeur « **confirmer/rejeter plutôt qu'inventer un
nombre** ». La calibration numérique fine des poids/seuils est déléguée à l'Epic 5 ; ici on
pose la mécanique et des défauts prudents, testables sans GPU via `MockRecognizer`. [Source: architecture.md#High Level Architecture] [Source: architecture.md#Architectural Patterns]

### Formule du score composite (défauts prudents — calibration Epic 5)

```python
# services/api/app/pipeline/confidence.py (structure)
from dataclasses import dataclass

@dataclass(frozen=True)
class ConfidenceResult:
    score: float          # 0..1, somme pondérée normalisée
    acoustic: float
    grammatical: float
    variant: float
    margin: float
    confusion: float

def composite_confidence(*, asr, normalized_text, number, candidates, settings) -> ConfidenceResult:
    s_acoustic    = asr.acoustic_score
    s_grammatical = 1.0 if zarma_numbers.parse_detailed(normalized_text).accepted else 0.0
    s_variant     = _variant_signal(normalized_text)        # via normalize_with_trace
    s_margin      = _margin_signal(candidates)              # top1 - top2 (candidats numériques)
    s_confusion   = _confusion_signal(candidates, lexicon)  # pénalité paire asr_confusions connue
    weights = (settings.CONF_WEIGHT_ACOUSTIC, ..., settings.CONF_WEIGHT_CONFUSION)
    score = sum(w*s for w, s in zip(weights, signals)) / sum(weights)
    return ConfidenceResult(score, s_acoustic, s_grammatical, s_variant, s_margin, s_confusion)
```

### Politique de décision

```python
# services/api/app/pipeline/policy.py (structure)
def decide(*, score: float, number: int | None,
           numeric_candidates: list, settings) -> Literal["accept","confirm","repeat"]:
    if number is None:
        return "repeat"                                   # FR21 : jamais inventer
    if len(numeric_candidates) >= 2 and _margin(numeric_candidates) < settings.POLICY_MARGIN_THRESHOLD:
        return "confirm"                                  # FR15/FR23 : ambiguïté
    if score >= settings.POLICY_ACCEPT_THRESHOLD:
        return "accept"
    if score >= settings.POLICY_CONFIRM_THRESHOLD:
        return "confirm"
    return "repeat"
```

### Contraintes techniques clés

- **Jamais de nombre inventé (FR21/NFR14)** : si `parse()` retourne `None` → `recognized_number = null`,
  `decision = "repeat"`. Aucun fuzzy matching décisionnel ; `asr_confusions` n'est **qu'un signal**,
  jamais un correcteur automatique. [Source: architecture.md#Coding Standards — « Jamais de nombre inventé »] [Source: docs/prd/requirements.md#FR8]
- **Variantes ≠ corrections ASR (FR8)** : deux tables distinctes dans `zarma_numbers` — la
  normalisation n'utilise que les variantes **linguistiques** ; les `asr_confusions` restent
  séparées et ne servent qu'au signal de confusion. [Source: architecture.md#Coding Standards — « Variantes ≠ corrections ASR »]
- **Backend-decides (FR13)** : toute la logique accept/confirm/repeat vit côté serveur ; le
  mobile **affiche** seulement la décision. [Source: architecture.md#Architectural Patterns] [Source: architecture.md#Frontend — « Aucune logique de décision numérique côté client »]
- **Isolation moteur linguistique** : `zarma_numbers` ne connaît ni FastAPI ni ASR ; tout le
  scoring/politique vit dans `services/api/app/pipeline/`, pas dans le paquet. [Source: architecture.md#Coding Standards — « Isolation du moteur linguistique »]
- **Config via settings** : poids/seuils lus via l'objet `Settings` (défauts prudents), jamais
  en dur dans la logique. [Source: architecture.md#Coding Standards — « Config via objet settings »]
- **Hors périmètre 2.5** : persistance/historique (2.6), rate limiting (2.7), calibration réelle
  des poids/seuils et matrice de confusions issue des données (Epic 5). [Source: docs/prd/epic-2] [Source: architecture.md#Architectural Patterns — Config-driven]
